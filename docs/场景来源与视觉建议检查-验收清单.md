# 场景来源与视觉建议检查：验收清单

## 状态与边界

- 来源检查与空间关系原型已实现；检查为建议，不阻断正常生成。
- 图像传输与只读约束有本地模拟供应商测试，不能据此宣称视觉模型会识别常识错误。
- 当前默认 `127.0.0.1:8080/health` 未连接成功；实际运行配置、视觉模型、图片案例仍需部署环境确认。
- 不自动覆盖正文、提示词、媒体或审核状态，不自动重试 GPU 生成。

## 配置前提

1. 设置中选择 llama.cpp，配置实际部署的视觉语言模型及 OpenAI-compatible 接口。
2. 只有服务器确实支持图片输入时，才勾选“启用图片理解”。该开关是用户声明，不是模型能力探测。
3. 当前检查读取 `UploadManager.InputDir()` 下的项目图片，与正式上传共用目录，不读数据库目录中的同名图片。
4. 仅支持本机可访问的项目 input PNG/JPEG/WebP，最大20 MiB。远程 SFTP 模式尚不支持此检查，不能以无法读取冒充检查通过。

## 来源检查回归

| 案例 | 预期 |
|---|---|
| 用户审核排除第二次出现的同一句 | 仅排除该次；不误报遗漏 |
| 正文修改导致排除来源哈希过期 | 不沿用旧排除决定 |
| 一句台词分到两个相邻镜头 | 拼接一致时不误报 |
| 同一句本应两次但只剩一次 | 提示次数不一致 |
| 本应一次却多出一次 | 提示额外重复，不归咎于“混合来源” |
| 尚无导演镜头 | 显示未评估，不显示已通过镜头检查 |
| 全部可分类引句被明确排除 | 说明已排除，不再要求产生这些对白 |
| 引号与未加引号的明确发声混合 | 无可靠映射时显示未评估，不推测语义完整性 |

## 真实图片案例

每个案例准备正确与错误各一张图。通过 Scene 正式上传/替换入口选图，然后点击“分镜图检查”，保留检查使用的模型名、时间、结果和人工判定；不把真实密钥、路径或图片字节写入日志。

### 皇帝与大臣

正文：皇帝坐在宝座上，大臣在宝座前面向皇帝参拜；摄影机从大臣后方拍摄。

- 正确：大臣面对皇帝，画面可见大臣背部。
- 错误：大臣背对皇帝，向相反方向参拜。
- 验收：不能把“背对摄影机”误判为“背对皇帝”；必须说明画面里的相互位置/朝向证据。
- 遮挡或距离不足以判断时，应返回无法判断，不臆测人物面部和身体朝向。

### 飞剑

正文：飞剑向敌人刺去，剑尖朝向敌人。

- 正确：画面明确可见剑尖指向目标，剑柄处在相反一端。
- 错误：画面明确可见剑柄指向敌人。
- 验收：检查功能端与目标的可见关系；静态图不能证明实际飞行方向、速度或完整轨迹。
- 剑身过小、拖影或遮挡时，应返回不确定，不以“飞剑通常如此”代替图片证据。

## 只读与并发

- 检查前后正文、图片、视频、候选采用状态、任务数量保持不变。
- 检查过程中修改正文、空间关系或替换图片：旧结果返回冲突或在界面被废弃，不显示为当前结论。
- 关闭并重新打开同场景弹窗：迟到请求不能覆盖新结果、错误或加载状态。
- 跨项目、路径穿越、符号链接越界、非图片输入不得发送给模型。

## 检查记录与修正闭环

1. 运行分镜图检查后，用户显式点击“保存检查记录”；每Scene只保留最近20条。此记录标明用户保存，不是不可伪造的AI审核证书。
2. 通过“查看检查记录”查看来源、时间与过期状态，不重新调用模型。输入变化的记录仍可查看，但不能用于当前修正。
3. 选择当前来源的记录，点击“整理修正提示词预览”。系统将建议编入现有提示词，而非再次调用AI重写整个故事；需人工检查是否仍有相互冲突的描述。
4. 对照原稿编辑预览，明确确认仅保存分镜图提示词。正文、Shots、视频、已有媒体和当前采用候选不变化，不启动图片生成。
5. 预览期间修改正文、关系、图片或提示词后，应用应返回409并保留编辑草稿；不能覆盖并发新稿。
6. 图片仍在生成时不应用修正，避免陈旧任务覆盖；待生成完成后重新预览。
7. 部署前备份SQLite数据库；检查记录新增Scene字段，经现有迁移初始化。
