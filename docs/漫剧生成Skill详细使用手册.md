# ComfyStudio 漫剧生成 Skill 详细使用手册

> 适用版本：2026-09-20（`main` 分支，包含 LumenX 导演工作流迁移）
> Skill 管理入口：左侧导航 **漫剧 Skill**
> Skill 执行入口：**漫剧工作台 → 打开项目 → 进入剪辑台**，或小说项目对应的分析/改编页面

---

## 1. Skill 是什么

Skill 是受控的创作方法与提示词契约。它负责告诉文本模型：

- 当前任务是什么；
- 可以读取哪些项目上下文；
- 必须输出什么结构；
- 哪些事实不允许改写；
- 结果是草稿、审查报告，还是可以进入下一生产阶段的数据。

Skill **不是**可以执行网络、Shell、文件或数据库操作的插件。它只参与提示词装配和结构化文本生成，业务服务负责校验、保存和执行。

### 1.1 管理入口和执行入口不是同一个地方

| 入口 | 作用 |
|---|---|
| **漫剧 Skill → 流水线技能** | 查看创作流程说明，不执行项目任务 |
| **漫剧 Skill → 技能管理** | 查看、启停、创建和编辑 Skill |
| **项目剪辑台/小说改编页面** | 使用具体 Skill 生成草稿或执行对应分析 |

因此，在 Skill 卡片详情中看到某项能力后，需要前往其业务页面点击对应按钮，才会真正调用该 Skill。

### 1.2 自动 Skill 与显式 Skill

Skill 分为两类：

1. **自动调用**：用户执行正常业务操作时，由系统自动选择相应 Skill，例如角色档案、章节分析和分集改编。
2. **显式调用**：必须由用户点击按钮，结果只生成草稿，审核后才能应用，例如视觉节拍、忠实润色和镜头覆盖审查。

## 2. 使用前准备

### 2.1 配置文本模型

进入 **平台设置**，确认文本模型已配置并通过连通性测试。Skill 使用当前平台配置的文本 Provider，包括：

- 火山 Ark；
- 本地 `llama.cpp`；
- MiniMax Coding Plan。

部分能力有额外要求：

- **看图润色**要求 Provider 真正支持多模态图片消息；
- 普通文本 Provider 不会把图片路径伪装成视觉输入；
- 不支持时页面会明确提示，不会静默降级为假看图。

### 2.2 检查 Skill 状态

进入：

```text
左侧导航 → 漫剧 Skill → 技能管理
```

检查需要使用的 Skill 是否启用。系统 Skill 默认启用，带有“系统”标记。

> 禁用某阶段/操作的 Skill 后，相应业务可能回退到内置基础提示词，也可能因该流程要求严格 Skill 而拒绝执行。不要在生产中随意禁用尚未理解的系统 Skill。

### 2.3 理解“操作契约”

同一阶段可以有多个 Skill，系统不仅按 `stage`，还按 `operation` 精确选择。例如视频提示词阶段包含：

- `director-shot-packet`
- `reference-shot-state-prompt`

自定义 Skill 的 `operation` 必须与调用入口要求完全一致，否则不会被该按钮使用。

## 3. 推荐的完整导演流程

```text
创作意图澄清
→ AI 完整 Scene 导演方案
→ 人工审核并导入 Shot
→ 逐镜扩写导演执行包
→ 补充镜头起止状态
→ 配置镜头造型覆盖
→ 资产连续性审查
→ 镜头覆盖度审查
→ 忠实润色或看图润色
→ 生成分镜图
→ 准备并审核 H3 完整提示词
→ 生成视频
→ 选择连续性尾帧
```

不是每个项目都必须执行全部步骤。短小、简单的场景可以直接使用 AI 导演方案；复杂动作、多人调度或连续镜头建议完整执行。

## 4. LumenX 导演 Skill 的入口与用法

## 4.1 创作意图澄清

**Skill code**：`creative-intent-elicitation`
**入口**：

```text
项目 → 剪辑台 → 跨集连续性 → 创作意图澄清
```

### 用途

在正式拆镜前澄清：

- 受众和情绪目标；
- 不可改变的设定；
- 可以自由发挥的范围；
- 尚未确定的创作选择。

### 操作

1. 点击 **创作意图澄清**；
2. 输入当前创作目标；
3. 系统提出 3–5 个会影响创作决策的问题；
4. 回答问题；
5. 系统整理为 Intent Brief。

### 输出与安全边界

输出是意图草稿，不会自动生成剧本、修改Scene或执行任务。

---

## 4.2 AI 完整 Scene 导演方案

**Skill code**：`director-scene-draft`
**入口**：

```text
项目 → 剪辑台 → 选择场景 → AI导演方案
```

### 用途

把一个 Scene 的剧情事实转换为完整的 Shot 导演草稿，包括：

- 叙事幕位置；
- 景别、机位和运镜；
- 时长；
- 镜头描述、对白和情绪；
- 转场；
- 起始状态与结束状态；
- 五段导演提示词；
- 自动检查项。

### 操作

1. 选择一个Scene；
2. 检查“场景概况”，默认会使用Scene剧情；
3. 可填写补充要求，例如：

   ```text
   情绪克制；保留全部原对白；不要远景；不要新增旁白；全程只使用缓慢推进。
   ```

4. 点击 **AI生成完整导演方案**；
5. 展开每个镜头查看起止状态和导演细节；
6. 不满意则放弃；满意后点击 **确认导入并保存**。

### 注意

- 生成结果只是草稿；
- 未确认前不会覆盖当前Shot；
- 确认导入会替换当前Shot导演设计，但不会改写Scene权威剧情和起始帧提示词；
- 已有重要Shot时，确认前应仔细核对。

---

## 4.3 导演视觉节拍拆镜

**Skill code**：`director-visual-beat-decomposition`
**入口**：

```text
项目 → 剪辑台 → 选择场景 → 高级导演工具 → 视觉节拍
```

### 用途

按“一个镜头一个主要可见动作或反应”的原则拆分剧情，重点解决：

- 一句话中堆叠多个动作；
- 对白没有相应反应镜头；
- 动作时间不足；
- 可见角色、仅发声角色和仅提及角色混淆。

### 操作

1. 点击 **视觉节拍**；
2. 查看生成的JSON草稿；
3. 确认镜头数、动作、对白和时长；
4. 点击 **导入Shot导演层**；
5. 在“高级：逐镜手工编辑”中继续调整并保存。

### 注意

导入会替换当前Shot设计。系统会二次确认，并保持Scene剧情正文和起始帧提示词不变。

---

## 4.4 导演单镜执行包

**Skill code**：`director-shot-packet`
**入口**：

```text
项目 → 剪辑台 → AI导演方案 → 高级：逐镜手工编辑
→ 某个镜头 → AI扩写镜头
```

### 用途

将简单镜头说明扩写为五段导演提示词：

1. 主体与五官；
2. 姿态与动作；
3. 摄影机与构图；
4. 光线与氛围；
5. 视觉风格与质感。

### 示例

简单说明：

```text
林采微听见门外异响，停下手中的动作并望向门口。
```

扩写时系统会结合：

- Scene剧情；
- 当前Shot时长；
- 起止状态；
- 已确认角色与资产；
- 当前场景/镜头套装。

### 使用建议

- 一镜只写一个主要动作；
- 动作必须能在当前时长内完成；
- 不要把人物完整外貌重新堆入文本，身份和造型由参考图控制；
- 保存Shot后，旧分镜图和视频会按规则失效，需要重新审核生成。

---

## 4.5 单镜起止状态导演提示

**Skill code**：`reference-shot-state-prompt`
**入口**：

```text
项目 → 剪辑台 → 高级：逐镜手工编辑
→ 填写起始状态/结束状态 → 起止状态草稿
```

### 用途

让单镜动作具有明确的开始和结束，便于：

- 控制动作是否可在时长内完成；
- 下一镜承接上一镜状态；
- 明确人物视线和注意力交接；
- 避免提示词只写剧情概括而没有可见轨迹。

### 示例

```text
起始状态：雷晓飞坐在桌旁，右手悬在桌面，视线低垂。
结束状态：雷晓飞已站起，身体转向厨房，视线落在门帘上。
```

点击 **应用到本镜五段** 后，草稿会填入五段提示词，但仍需人工检查并点击 **保存导演设计**。

---

## 4.6 忠实最小改动润色

**Skill code**：`director-faithful-prompt-polish`
**入口**：

```text
项目 → 剪辑台 → 选择场景 → 忠实润色
```

### 用途

只改善用户指定的视觉表现，不改变：

- 角色；
- 剧情动作；
- 对白原文；
- 地点、道具和空间关系；
- 镜头目标；
- 用户明确指定的风格。

### 反馈示例

```text
增强人物动作可见性，保持人物、对白和场景陈设不变。
```

```text
只改善侧逆光层次，不改变构图和人物位置。
```

### 操作

1. 点击 **忠实润色**；
2. 输入希望改善的部分；
3. 查看草稿；
4. 点击 **应用到Scene起始帧提示词**。

系统不会自动保存或生成图片，应用后仍需按正常流程保存/生成。

---

## 4.7 看图润色

**入口**：

```text
项目 → 剪辑台 → 选择已有分镜图的场景
→ 高级导演工具 → 看图润色
```

### 用途

让支持视觉输入的文本模型直接观察当前分镜图，再根据真实的：

- 构图；
- 人物位置；
- 光线；
- 色调；
- 已存在物体；

生成忠实的润色草稿。

### 限制

- 当前Provider必须真实实现多模态消息；
- 不支持时系统明确提示“当前文本模型不支持图片输入”；
- 不会将本地图片路径当成图片内容发送；
- 结果仍是草稿，需要人工应用。

---

## 4.8 资产连续性检查

**Skill code**：`reference-asset-continuity`
**入口**：

```text
项目 → 剪辑台 → 选择场景
→ 高级导演工具 → 资产连续性审查
```

### 检查内容

- 人物外观与本场造型；
- 鞋履、发型、发饰、首饰、包等造型资产；
- 道具持有状态；
- 场景布局；
- 时间、天气和光线；
- 伤势、知识和关系状态；
- 上一镜结束状态与当前镜头是否冲突。

### 输出

只输出审查草稿和冲突，不会自动修改资产、Scene或Shot。

---

## 4.9 分镜覆盖度审查

**Skill code**：`reference-coverage-review`
**入口**：

```text
项目 → 剪辑台 → 选择场景
→ 高级导演工具 → 镜头覆盖审查
```

### 检查内容

- 剧情信息是否有可见画面承载；
- 是否缺少建立镜头；
- 是否缺少主要动作；
- 是否缺少人物反应；
- 是否缺少关键细节；
- 转场是否成立；
- 是否存在重复镜头。

建议只补“最小必要镜头”，不要为了镜头数机械拆分。

## 5. 其他自动调用的生产 Skill

## 5.1 角色档案 Skill

**入口**：项目详情的角色档案生成、重新生成和审核操作。

系统从故事或创作方案自动生成角色草稿，再由用户编辑、批准或驳回。批准前不要直接生成最终角色资产。

角色标准像与造型资产职责分离：

- 标准像提示词只描述简洁的脸部身份；
- CharacterLook只描述一个独立造型资产；
- CharacterOutfit组合多个已审核造型；
- 武器、法宝和剧情物品仍属于`prop`。

## 5.2 Krea2 巨构场景增强

**Skill code**：`krea2-megastructure-prompt`
**入口**：场景编辑时将视觉类型设为“巨构场景”，然后重新设计/生成场景提示词。

它会增强：

- 可测量的尺度参照；
- 结构重复单元；
- 大气透视；
- 重量感；
- 镜头和景深层次。

它不得改变剧情主体、角色、动作、颜色和关键道具。

## 5.3 H3 视频提示词 Skill

入口是剪辑台中的：

```text
准备并审核视频提示词
```

系统会按当前模板分别编译：

| 模式 | 协议 |
|---|---|
| T2VA | 三字段关键帧协议 |
| I2VA | 三字段关键帧协议，首帧硬锚定 |
| FL2VA | 三字段关键帧协议，首尾帧 |
| Ref2VA | 六段多参考协议 |

用户必须在GPU提交前审核完整提示词。剧情、人物分类、对白或参考图变化后，旧完整提示词会标记失效。

## 6. 长篇小说改编 Skill

长篇小说Skill主要在小说项目的业务页面自动触发。

## 6.1 章节分析

**入口**：

```text
项目详情 → 小说导入 → 分析章节
```

输出章节摘要、事件、人物、地点、道具、冲突和未闭合线索。分析任务支持断点恢复。

## 6.2 故事弧合并

系统默认按约8章组成一个故事弧，也可按项目规划在5–10章范围内调整。它只合并已有章节分析，不允许补写原文没有的事实。

## 6.3 小说 Story Bible

**Skill code**：`novel-story-bible`
**入口**：

```text
项目详情 → Story Bible → 生成/重新生成
```

内容包括：

- 世界规则；
- 主线和支线；
- 时间线；
- 角色关系；
- 伏笔账本；
- 地点和道具。

Story Bible必须人工审核通过后，才能进入正式改编规划。

## 6.4 小说分集映射

**Skill code**：`novel-episode-mapping`
**入口**：

```text
项目详情 → 改编方案 → 生成分集映射
```

默认按每集约180秒、25镜头映射原著章节，记录：

- 必保事件；
- 可选事件；
- 省略事件；
- 开场和结束状态；
- 集尾钩子；
- 原文来源章节。

## 6.5 小说单集剧本改编

**Skill code**：`novel-episode-script`

只使用当前集有界上下文和已批准Story Bible，不应把整部长篇一次性塞入模型。

## 6.6 小说连续性复审

**Skill code**：`novel-continuity-review`

检查前集结束、本集开场和本集结束之间的：

- 地点；
- 时间；
- 伤势；
- 持有物；
- 人物知识；
- 关系；
- 因果。

冲突会形成审查建议，不应静默改写剧情。

## 7. Skill 管理

## 7.1 查看详情

进入：

```text
漫剧 Skill → 技能管理 → 点击眼睛按钮
```

可查看：

- 名称和版本；
- 阶段；
- 操作契约；
- 描述；
- 提示词模板；
- 系统提示词；
- 启用状态。

流水线卡片也可直接点击，详情弹窗会显示输入、输出、模型、参数、步骤和相关API。

## 7.2 启用与禁用

点击Skill右侧开关即可修改全局启用状态。

建议：

- 生产环境不要直接禁用系统Skill；
- 先复制为自定义Skill做实验；
- 自定义Skill验证通过后再调整项目配置；
- 禁用前记录原版本和用途。

## 7.3 新建自定义 Skill

点击：

```text
技能管理 → 新建自定义技能
```

填写：

| 字段 | 说明 |
|---|---|
| 技能名称 | 页面显示名称 |
| 技能代码 | 稳定、唯一的英文标识 |
| 适用阶段 | Skill所属流水线阶段 |
| 操作契约 | 必须与业务按钮要求的operation一致 |
| 描述 | 适用范围和限制 |
| 提示词模板 | 支持`{{param}}`参数 |
| 系统提示词 | 输出结构、禁止事项和质量要求 |

### 自定义导演单镜Skill示例

```text
名称：克制悬疑单镜执行包
代码：restrained-thriller-shot
阶段：video_prompt
操作契约：director-shot-packet
```

模板中应使用业务提供的参数，例如：

```text
镜头事实：{{scene_content}}
角色与资产：{{asset_context}}
起始状态：{{start_state}}
结束状态：{{end_state}}
时长：{{duration}}秒
```

输出仍需遵守`subject/action/camera/lighting/style`五段JSON契约，否则业务接口会拒绝。

## 7.4 版本与审核

Skill以`(code, version)`区分版本。升级应从最新版本派生，不要直接破坏已运行项目所依赖的旧行为。

系统记录Skill调用审计，包括：

- 项目；
- 阶段和操作；
- 使用的Skill版本；
- Provider；
- 成功或失败；
- 错误摘要。

## 8. 草稿、应用和执行的区别

界面文案中的三个词含义不同：

| 状态 | 含义 |
|---|---|
| **生成草稿** | 只得到AI建议，数据库权威内容未改变 |
| **应用/导入** | 将草稿填入Scene或Shot编辑层，通常仍需保存 |
| **保存并生成** | 保存审核结果并提交实际图片/视频任务 |

使用导演Skill时应遵守：

```text
AI生成 → 人工审核 → 应用/导入 → 保存 → 生成
```

不要把“生成草稿成功”理解为已经修改项目或提交GPU任务。

## 9. 常见问题

### 9.1 点击Skill卡片详情没有反应

请确认代码至少包含提交：


### 9.2 Skill按钮提示未配置文本模型

进入平台设置，保存文本Provider配置并执行连通性测试。

### 9.3 点击按钮后只有草稿，没有修改项目

这是预期行为。视觉节拍、忠实润色、资产连续性和覆盖审查都采用“先草稿、后人工应用”的安全流程。

### 9.4 自定义Skill没有被调用

检查：

1. Skill是否启用；
2. `stage`是否正确；
3. `operation`是否与按钮要求完全一致；
4. 输出结构是否满足业务契约；
5. 项目是否有显式配置覆盖该操作；
6. Skill审计记录中是否有失败信息。

### 9.5 Skill生成了多余人物或道具

- 检查Scene的“画面可见/仅发声/仅提及”人物分类；
- 检查参考图绑定；
- 使用资产连续性审查；
- 在补充要求中明确“不得新增剧情人物和关键道具”；
- 不要在提示词中重复猜测参考图已经控制的视觉细节。

### 9.6 修改Skill后旧项目为什么没有变化

可能原因：

- 项目配置固定了某个Skill版本；
- 使用的是不同operation；
- 页面展示的是已经保存的提示词；
- 完整H3提示词需要重新生成并审核；
- 运行时仍在使用旧后端进程。

更新代码后应重新构建、重启后端；运行时工作流JSON发生变化时，还需要调用模板重载接口或重启服务。

### 9.7 如何确认实际使用了哪个Skill

查看：

- 接口响应中的`skill_code`；
- 项目Skill审计记录；
- 后端日志；
- 提示词历史版本和动作来源。

## 10. 最佳实践

1. 先建立并审核角色、造型、场景和道具资产，再生成导演方案。
2. Scene保存剧情事实，Shot保存导演表达，不要让Shot反向改写剧情。
3. 复杂Scene先运行视觉节拍，再运行完整导演方案或逐镜扩写。
4. 连续镜头必须填写起始/结束状态，并在视频完成后人工选择尾帧。
5. 资产连续性审查在分镜图生成前执行，覆盖度审查在Shot设计完成后执行。
6. 忠实润色只写需要修改的部分，避免要求模型重写整个提示词。
7. H3完整提示词必须人工审核后保存；参考图变化后重新确认。
8. 自定义Skill先在副本或测试项目中验证，不直接替换生产系统Skill。
9. 遇到输出结构错误时先检查Skill契约，而不是放宽后端校验。
10. 任何AI结果都应保持“草稿可审、应用可追踪、生成可回滚”。
