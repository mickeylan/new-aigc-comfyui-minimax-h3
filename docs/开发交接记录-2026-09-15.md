## 4. 四视图问题与失败实验

### 4.1 原始问题

角色四视图中的三个全身站立图常出现：

- 赤脚；
- 三个视角鞋履不一致；
- 背面换装；
- 发型、佩饰和人物身份漂移。

### 4.2 已验证无效的方案

#### 只增加鞋履正向/负向提示词

改善不稳定。原因是输入为半身大头照，没有鞋的视觉信息，模型仍需猜测下半身。

#### 用大头照图生图生成“全身锚点”

失败：Krea2 保留原图构图，生成的所谓全身锚点仍是半身图。

#### 独立文生图生成全身锚点

失败：虽然可能生成全身，但脸、发型、头部佩饰和人物身份明显漂移。

#### 大头照与全身锚点横向拼接后生成四视图

失败：模型容易把拼接图理解成两个人或两套造型，背面直接换装。

#### 四视图只引用全身锚点

失败更严重：丢失大头照中的发型、佩饰和人物身份。

### 4.3 当前决定

完整撤销全身锚点方案，恢复：

```text
人物正面大头照 -> Krea2 角色四视图
```

暂时只保留鞋履文字约束，不增加中间生图步骤。

## 5. 下一阶段正确方向：角色造型资产

不要再次实现“重画整个人物的锚点”。更合理的是增加独立、可审核的角色造型资产。

### 5.1 穿戴造型资产

尤其针对女性角色：

- 鞋履：日常、战斗、宴会、旅行等多套；
- 包包或随身容器；
- 发型和发饰组合；
- 发簪、步摇、发冠；
- 耳环、耳坠；
- 项链、吊坠；
- 手镯、腕饰、戒指；
- 腰带、腰佩。

每项需要：名称、分类、外观描述、参考图、审核状态、适用剧情/场景、是否默认。

### 5.2 手持和剧情资产

- 兵器：剑、刀、枪、弓等；
- 法宝、法器；
- 符箓、灵珠、法印、玉佩等。

这些应继续归入道具资产体系，按镜头选择性引用，不能永久固化到人物四视图，否则角色会在不需要时也携带。

### 5.3 推荐数据设计

可新增角色造型模型，例如：

```text
CharacterLook
- ID
- ProjectID
- CharacterID
- Name
- Description
- Hairstyle
- Accessories
- Footwear
- Bag
- Image
- ImageTaskID
- ImageError
- Approved
- IsDefault
```

再增加 Scene/Shot 与造型、道具的关联。不要把所有选择塞进 `Character.WardrobeDetail` 字符串。

### 5.4 引用策略

- Krea2 Scene 图：人物标准像/四视图 + 当前造型资产 + 当前场景/道具。
- MiniMax H3 视频：继续引用 Scene 图；只有镜头明确拍到鞋履、佩饰、包包、兵器或法宝时，才加入对应资产参考图。
- 保持 H3 最多 9 张参考图，按镜头可见性和重要性排序。

注意：H3 当前生成的是视频，不是 Scene 场景图。

## 10. 关键经验

- 大头照负责身份一致性，不能被全身图替代。
- 不要把多张不同构图的人物图横向拼接后交给 Krea2，容易被理解为多人或多造型。
- 提示词是软约束，无法可靠补齐输入图中完全不存在的视觉细节。
- 鞋履、包包、配饰、发型、兵器和法宝应该是可选择、可审核、按剧情引用的资产。
- 不要为了修复鞋履而牺牲更重要的人脸、发型、服装和人物一致性。
