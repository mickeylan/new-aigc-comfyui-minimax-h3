# LumenX 精华借鉴实施方案（画布置于最终阶段）

> 日期：2026-09-19
> 状态：实施中
> 技术边界：保持 Go + Gin + GORM + SQLite + Vue 3；当前阶段不引入画布。Canvas仅在数据模型、API、审核与历史链路稳定后作为最终阶段评估和实现；不迁移到React、Next.js、Tauri、Electron、Tiptap或JSON文件数据库。

## 1. 目标

在现有漫剧生产链中吸收 LumenX 已验证的生产思想，而不是复制其界面和技术栈：

1. 稳定 Episode → Scene → Shot 的集/场/镜结构。
2. 把 Shot 明确为导演设计单元，保留五段提示词、镜头参数、对白、情绪与持续时间。
3. 补齐提示词工作台的构建、优化、翻译、历史、真实回滚和项目隔离。
4. 让风格推荐基于项目、场景和镜头上下文，并显示可解释的推荐理由。
5. 筛选引入少量 LumenX 提示词方法，保持 Skill 为无执行权限的模板。
6. 后续引入生成候选 Takes、审核与可追溯输入快照，不再覆盖唯一结果。
7. 长期将对白、环境声、背景音乐分层管理，减少联合音频生成的不确定性。

## 2. 当前阶段不做的内容

- 当前阶段不实现画布、节点编辑器或自由布局工作台；Canvas列入最终Phase，不能阻塞结构化生产能力。
- 不迁移到 Python/FastAPI、React/Next.js、Tauri/Electron。
- 不照搬 LumenX 页面、CSS 或组件。
- 不用 Tiptap 替换现有编辑器。
- 不恢复已证明效果不佳的全身服装锚点流程。
- 不允许 Skill 执行网络、Shell、文件或数据库操作。
- 不在用户打开或保存提示词时自动覆盖用户内容。

## 3. 当前基线

### 已具备

- `Scene.EpisodeN` 和 `Shot.SceneID` 已形成逻辑集/场/镜关系。
- `Shot` 已包含五幕位置、景别、机位、运镜、时长、描述、对白、情绪及五段导演提示词。
- Vue 已有 `ShotDirectorEditor`，支持五幕骨架和五段编辑。
- 后端已有 Prompt Workshop：build / optimize / translate / history / rollback。
- 已有风格预设、基础推荐逻辑及推荐理由字段。
- 已有版本化、受限执行的 Skill 框架和三条参考型 Skill。

### 关键缺口

1. `ReplaceShots` 删除重建镜头，导致 Shot ID、提示词历史和镜头关联失效。
2. 前端保存时丢弃 Shot ID。
3. PromptVersion 虽有 `ProjectID`，服务却未写入或按项目过滤。
4. 新镜头用 `entity_id=0` 调用优化，多个草稿共享错误历史身份。
5. 前端没有调用 Prompt Build，也没有调用真正的 Rollback API。
6. 五段提示词靠分号/换行拆分，AI普通 prose 可能被错误放入风格段。
7. 风格推荐接口未被镜头编辑器使用，展示的是静态理由而非当前上下文匹配理由。
8. Episode 仍主要是 `Scene.EpisodeN` 标签，尚非完整聚合实体。
9. Scene/Shot生成结果仍是覆盖式单文件，缺少 Takes 与审核状态。

## 4. 实施阶段

## Phase 0：稳定已有导演能力（立即实施）

### 4.1 Shot ID 保持与关联安全

- 将 `ReplaceShots` 改为事务内 upsert：
  - 请求中带 ID 且属于当前 Scene：更新并保留 ID。
  - 请求中无 ID：创建新 Shot。
  - 数据库中存在但请求未包含：删除该 Shot。
  - 顺序统一重排，避免唯一索引冲突。
- 前端保存时保留 `id`。
- 删除 Shot 时同步删除或保留明确策略下的关联数据；PromptVersion 保留为历史审计但不能串到新 Shot。
- 回归测试：保存两次后 ID 不变，新增/删除/重排正确，跨 Scene ID 被拒绝。

### 4.2 Prompt Workshop 项目隔离

- 所有 Prompt Workshop 请求必须携带 `project_id`。
- 服务端验证：
  - `entity_type=shot` 时 Shot 必须通过 Scene 属于 Project。
  - `entity_type=scene` 时 Scene 必须属于 Project。
  - `entity_type=skill` 时按技能权限规则校验。
- `PromptVersion.ProjectID` 必须写入并参与 history/version/rollback 查询。
- 拒绝 `entity_id=0` 写历史；未保存镜头的 AI 扩写只返回草稿，不产生历史。
- 迁移策略：旧 `project_id=0` 历史只读，不自动错误归属。

### 4.3 完整提示词工作台交互

- 增加“按五段构建”按钮，调用 `/api/prompts/build`。
- 优化/翻译要求返回稳定五段结构；优先使用 JSON 对象：
  - `subject`
  - `action`
  - `camera`
  - `lighting`
  - `style`
- 历史版本点击“回滚”时调用后端 rollback API，而非只在前端赋值。
- 保存镜头时记录 manual 版本；同内容去重。
- 用户编辑内容始终是权威值，AI结果只作为可审核草稿。

## Phase 1：上下文风格推荐与精选 Skill

当前进度：可解释风格推荐的后端结构、API响应和镜头编辑器接入已完成；首批精选Skill（视觉节拍拆镜、导演单镜执行包、忠实最小改动润色）已完成幂等内置。`director-shot-packet`已接入保存后Shot的“AI扩写镜头”入口，支持项目显式配置优先、精选Skill兜底，并写Skill审计日志。第三方MIT声明已写入`THIRD_PARTY_NOTICES.md`。

### 4.5 可解释风格推荐

- 推荐输入：项目题材/画风、Scene标题/内容/地点、Shot景别/情绪/光线/叙事幕。
- 推荐输出：
  - preset
  - score
  - matched_fields
  - reasons
- 镜头编辑器默认展示 2–3 条上下文推荐，并保留“浏览全部预设”。
- 应用前显示将追加的正向词、负向词和原因；避免重复追加。
- 记录应用的 preset ID 和版本到 PromptVersion metadata。

### 4.6 精选 LumenX Skill（MIT）

只重写并引入方法，不复制前端和框架代码。若使用实质性原文，新增 `THIRD_PARTY_NOTICES.md`，注明 Alibaba LumenX MIT 来源。

首批候选：

1. `director-visual-beat-decomposition`
   - 一镜一个主要可见动作。
   - 多动作拆镜。
   - 单镜一个主要发声者。
   - 景别、机位、时长受控。
2. `director-shot-packet`
   - 主体调度、动作、摄影机、光线、连续性、声音提示。
   - 映射到现有 Shot 字段，不扩张无用 Schema。
3. `director-faithful-prompt-polish`
   - 区分不可变剧情事实与可丰富的视觉表现。
   - 禁止新增剧情、角色、对白和心理旁白。
4. `creative-intent-elicitation`（后续）
   - 仅用户明确触发。
   - 最多 3–5 个问题。
   - 输出 Intent Brief，不自动执行。

Skill要求：

- 固定版本、稳定 Code、幂等初始化。
- 明确输入参数和输出格式。
- 仅提示词模板，无执行权限。
- 真实调用必须写 `SkillAuditLog`。

## Phase 2：Episode 聚合与生产状态

当前进度：通用Episode实体、GORM迁移、从现有Scene与Plan幂等回填、Episode→Scene→Shot只读层级API及剪辑台集导航接入已完成；Episode编辑CRUD和Shot生产状态尚待实施。

### 4.7 Episode 实体

新增通用 `Episode`，但保留 `Scene.EpisodeN` 兼容字段：

- `ProjectID`
- `Number`
- `Title`
- `TargetDuration`
- `TargetScenes`
- `Status`
- `Version`

迁移：根据现有 Scene 的不同 `EpisodeN` 幂等回填，不删除旧字段。API返回 Episode → ordered Scenes → ordered Shots。

### 4.8 Shot生产状态

先确定产品语义：

- Scene仍是生成单元：Shot只做导演规划，UI明确标注。
- 或Shot升级为生成单元：增加任务、缩略图、状态和候选关联。

在未作决定前，不同时宣称两者都是生成权威来源。

## Phase 3：候选 Takes 与审核

新增 `GenerationCandidate`：

- entity type/id
- media type
- task/file
- prompt snapshot
- reference snapshot
- params snapshot
- skill/preset provenance
- review status/reason
- parent candidate

交互：候选比较、设为当前、拒绝原因、同参数重试、基于候选分支。`Scene.ImageFile` / `VideoFile` 逐步变为当前候选指针，而非唯一历史。

## Phase 4：音频分层

- Dialogue：明确说话人、类型、发声位置、音色描述、正文。
- 环境/动作声：soundscape。
- BGM：non-diegetic music。
- 角色音色与真实TTS可独立生成，文本/音色变化后标记 stale。
- 合成阶段控制Dialogue、H3原生音频、BGM音量。
- 该阶段为中期能力，不要求用户改ComfyUI工作流。

## Phase 5：模型能力Catalog与共享资产池

### 4.9 Model Catalog

轻量数据化：模式、模板、最大引用数、首尾帧支持、音频支持、分辨率、时长和默认参数。前后端均从Catalog读取，不散落硬编码。

### 4.10 策展式共享资产池

层级：全局共享 → 项目 → Scene/Shot。

- 只允许用户显式录入。
- 不自动吞入生成结果。
- 区分活引用与本地副本。
- 被引用资产不可直接硬删。

## 5. 数据与兼容策略

- 所有Schema变更使用GORM AutoMigrate，迁移幂等。
- 保留旧字段和旧API至少一个兼容周期。
- 不自动重写用户已保存提示词。
- 不自动替换已有生成资产。
- 新逻辑必须对旧项目空字段提供保守回退。
- 每一步单独测试、构建、审查Diff后再进入下一步。

## 6. 安全与许可证

- LumenX根许可证为MIT（Copyright © 2026 Alibaba）。
- 借鉴概念时独立重写；复制实质性内容时保留MIT声明。
- Skill继续保持无网络、Shell、文件和数据库执行权限。
- 项目级Prompt/Skill接口必须验证资源归属，避免跨项目读取或回滚。

## 7. 验收标准

1. 同一Shot反复保存ID不变化，历史不丢失。
2. 项目A不能查看或回滚项目B的PromptVersion。
3. 未保存Shot的AI草稿不会写入`entity_id=0`历史。
4. 五段构建、优化、翻译、历史、回滚均可在现有Vue界面完成。
5. 风格推荐理由随Scene/Shot上下文变化。
6. 精选Skill幂等初始化、版本明确、输出兼容当前解析器。
7. 全程没有新增Canvas、React、Next、Tauri或Electron依赖。
8. 后端完整测试、前端测试与构建通过。

## Phase 6：Canvas（最终阶段）

前置条件：Episode/Scene/Shot、PromptVersion、GenerationCandidate、资产继承、音频分层和Model Catalog均已稳定。

实施前单独完成产品决策：

- 画布定位：关系可视化、镜头时间线，还是节点式生产编排。
- 画布数据必须是现有后端实体的投影视图，不能创造第二套事实来源。
- 优先在现有Vue架构中实现；如需第三方画布库，必须单独评估体积、许可、无障碍、性能和维护成本。
- 所有画布操作必须落回既有API，离开画布后数据仍完整可编辑。
- 不直接复制LumenX画布界面或其React实现。
