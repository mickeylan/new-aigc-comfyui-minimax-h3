# ADR-0002：受控扩展与影子依赖图

- 状态：Accepted
- 日期：2026-10-23

## 背景

漫剧生产系统已经由领域模型和服务管理角色、资产、Scene、Shot、Dialogue、连续性、生成候选、审核状态、失效传播及 ComfyUI 任务恢复。引入文件化 Skill、模型能力声明、Agent 工具、生成适配器和 Artifact 依赖图，可以改善扩展性、诊断和局部重跑，但如果形成第二套执行或状态权威，将破坏现有审核门禁和任务恢复机制。

## 决策

1. 所有扩展能力默认关闭；关闭时不得改变既有生产行为。
2. 数据库领域表、领域服务及其 `stale/current/hash/review` 逻辑继续是生产状态权威。
3. Artifact 依赖图是影子图：只记录可由权威字段证明的血缘和失效审计，不直接驱动领域状态变更。
4. 依赖边必须绑定 `project_id`，使用受控 Artifact kind，并在领域事务内写入或清理。
5. 优先记录具有硬关联的边：Music Cue → Music Candidate、Dialogue → Dialogue Audio Candidate、连续性候选帧 → 使用该帧的 Scene Video。分镜图 → 视频仅在已有权威任务或候选关联能够证明来源时记录，不根据文件名或界面选择臆测。
6. Agent 工具仅调用受限的领域读模型；禁止 Shell、任意文件、原始数据库、不受限网络和绕过审核的生成提交。写入与生成权限仍需显式人工批准引用。
7. Template 和 TaskService 继续分别作为可执行工作流与任务提交/恢复的权威。Generation Adapter 不得形成第二条提交路径。
8. 没有真实、启用且验证过的 MiniMax Music 3 模板时，仅保留 Cue、候选审核和未就绪诊断，不创建生成任务，不创建 AudioLayer。
9. AI 制片检查是只读诊断：输出缺失引用、过期产物、未审核输入和受影响范围，不自动修复、审核或提交任务。
10. 历史数据允许依赖图为空；系统不得把“图中没有边”等同于“没有业务依赖”。

## 理由

- 领域服务已经包含经过测试的事务、审核和失效规则，影子图只补充统一的影响查询和审计。
- 使用权威外键、任务 ID 和版本哈希建边，可以避免从自由文本或文件名推断依赖。
- 默认关闭和无数据兼容允许渐进部署、回滚和历史项目继续运行。
- 保持 Template 与 TaskService 单一权威，避免插件或 Agent 绕过 GPU 调度、任务恢复和旧结果覆盖保护。

## 后果

### 正面

- 可以跨领域查询一个上游变化会影响哪些候选和产物。
- 可为只读 AI 制片检查提供稳定、可审计的生产上下文。
- 支持逐域接入而不要求一次性迁移全部历史数据。
- 尚未安装的生成能力会明确显示未就绪，不会伪造任务。

### 代价

- 领域写入路径需要同步维护影子边和删除清理。
- 依赖图可能不完整，调用方必须与领域状态联合判断。
- 新增 Artifact kind、事务一致性、项目归属和循环检测测试。
- Agent 工具的只读边界主要由受限服务接口和测试保证，不是操作系统级沙箱。

## 约束

- 所有图查询、建边、删除和检查必须校验 `project_id`。
- 不允许任意字符串 Artifact kind；新增 kind 必须进入受控注册表并有领域归属校验。
- 建边和领域产物写入必须尽可能处于同一事务；事务回滚不得留下孤立边。
- 领域失效成功但影子审计失败时，调用路径必须返回错误或记录明确告警，不能宣称完整成功。
- 删除领域产物时必须清理其作为上下游的边；不能依赖数据库外键级联。
- 只读检查不得返回密钥、完整提示词、用户原文、任意文件路径或原始工具输入。
- 不提交 `.rscode/**`、生成的可执行文件或无关本地文档。
