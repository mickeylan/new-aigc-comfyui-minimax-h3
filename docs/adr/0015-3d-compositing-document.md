# ADR-0015：3D合成层与完整工程存档

状态：已实施并完成下列验收；未提交、未推送。用户授权记录ADR后实施。

## 决定

对照本地 ArtCraft `frontend/libs/components/pagescene/src/lib/engine`，复用现有Three场景与素材能力，不引入新框架。每个平面持有独立设置；图片软边透明与视频色键不由全局UI状态决定。保留上游许可声明。

场景文档升级v4，兼容读取v1–v3。图片/视频平面及天空盒作为独立文档成员保存媒体字节、变换与参数，不存临时blob URL；几何GLB不重复携带平面。稳定ID用于新档身份，旧档保留原回退。沿用后端32MiB存档上限，超限明确失败，不静默删层。GLB格式本身不支持视频，不将GLB导出等同工程保存。

截图与身份迁移复用干净取景路径，隐藏编辑辅助物并恢复状态。新工程载入要清除旧天空盒并释放旧媒体资源；失败必须显示错误，不宣称恢复成功。

## 范围

本次补合成闭环，不扩到完整对象动画时间线、多机位系统或图像反求相机。不改现有2D工作、不真实AI生成、不部署提交推送、不触碰18000。

## Character Posing 正确性修复

- GLB与场景几何改用SkeletonUtils克隆，确保SkinnedMesh引用克隆骨架；剔除FK红球。截图、身份迁移/机位出图、首尾帧、参考图、缩略图统一隔离骨骼操作柄/红球/骨架线，并在finally恢复可见性；缩略图和深度范围也不计算红球边界。
- v4增补可选`objects[].initialBonePose`，保存当前实时骨姿，不再依赖是否点过内存记忆；初始骨姿独立保存。旧档仍可读取，但未记录原始姿势的历史存档无法反推出真正原始姿势，回退为载入GLB的姿势，需重新导入原模型才能恢复原始绑定姿。
- 骨姿先校验结构、有限数、非零四元数、循环、128层深度及4096节点上限；支持独立多骨树、同名子骨，保留改名兼容；匹配不完整时原子拒绝，不部分写入或假报成功。载入时先校验，不替换原场景。
- 面板明确“保存姿势（内存）”与场景持久化区别；还原/初始增加覆盖确认，摆姿模式禁用整体移动/旋转/缩放入口，统一可摆骨判定。共享红球几何体只释放一次。
- 新增`posing/poseExport.spec.ts`六项行为测试：真正SkinnedMesh GLB导出/重载、骨架引用独立、当前/初始姿势分离、辅助物过滤与异常恢复、坏存档边界、重复名/缺骨/多根、根骨祖先和大四元数。与原11项骨姿用例合计17项通过。
