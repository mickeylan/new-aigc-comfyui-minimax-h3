# ADR-0010：预演时间轴本地视频导出

状态：用户已授权实现；本地回归后待用户决定是否提交；未部署。

扩展ADR-0008的导出能力，仍是旁路：不进入生成链，不改Scene、Shot、对白、站位、提示词与预演文档。

## 决策

- 格式：WebM（VP9优先，浏览器不支持时退回VP8），1280×720，无音轨。用浏览器 WebCodecs `VideoEncoder` 逐帧编码，自带最小 Matroska 封装，不新增第三方依赖。不用 `MediaRecorder`：它按墙钟计时，渲染慢时会丢帧或变速，不能保证帧时间与时间轴一致。
- 帧时间：与PNG序列相同，`from + i×1000/fps`，起点包含、终点不含；FPS沿用1/6/12/24；帧时间戳按帧序号确定，不受渲染耗时影响。每2秒（至少每帧数1）一个关键帧并写入Cues，便于拖动定位。相机硬切沿用时间轴采样结果。
- 上限：时长不超过预演文档时长（最长120秒），最多2880帧，编码结果不超过256MiB；超限拒绝，不截断。导出可取消，取消或失败不下载残缺文件。
- 画面：沿用ADR-0008的白模与深度通道（排除网格、箭头、A/B标记、选中高亮、天气粒子和雾）；模型未恢复时拒绝导出，不以占位体替代。深度视频经有损编码与色度抽样，只供审阅运动与机位，精确深度仍须用PNG序列。
- 交付：浏览器本地生成ZIP，内含 `.webm` 与 `manifest.json`（场景ID、已保存revision、是否含未保存修改、模式、编码、分辨率、FPS、区间、帧时间、深度映射、导出时文档）。不上传服务器，不进入ComfyUI，不自动写入素材库。
- 不支持 WebCodecs 或 VP9/VP8 编码的浏览器：明确提示改用PNG序列，不降级到 `MediaRecorder`。

## 不在本期

带材质/天气的预演外观视频、音轨或对白混入、MP4/H.264、服务器端转码、接入生成链或深度控制节点、Shot绑定帧视频。

## 验证

- 前端单元测试覆盖帧时间与上限、编码调度（关键帧间隔、时间戳、背压、取消、编码错误、体积上限、编码器关闭）与 WebM 结构（EBML头、Info时长、轨道编码、簇时间码、关键帧标志、Cues指向簇位置）。
- `npm --prefix frontend test`：348/348 通过（新增7项）；`npm --prefix frontend run build`：exit 0。预演组件 54.48 kB / gzip 19.99 kB，仍懒加载，无新依赖。
- 浏览器隔离测试桩（Chromium，无后端）：白模与深度均选中 VP9；导出的 WebM 由浏览器 `<video>` 解码为 1280×720、时长 3.000 秒（0～3秒、12 FPS、36帧），首/中/尾帧均非空白，白模与深度画面可区分；manifest 正确标记已保存与含未保存修改两种状态；10秒/24 FPS 导出中途取消不下载。未调用真实服务或生成任务。
- 未验证：Firefox/Safari 的 WebCodecs 支持差异、长时长（接近2880帧）导出耗时与内存。
