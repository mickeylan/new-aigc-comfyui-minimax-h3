# ADR-0033：执行动作片段的源区间与速率（C3）

- 状态：已实现；单元/组件与隔离浏览器通过，非 Stage 播放验收
- 前置：ADR-0024 C2b/C2c、ADR-0026

## 背景

执行片段的骨骼 clip 目前恒从 0 秒开始按镜内秒播放，走完 clip 后停在末帧。人工常需要“只取这段动作的后半段”或“慢放/快放”，但既有契约明确不做自动重定时，也不按名称猜动作语义。C3 补齐**人工显式**的源区间与速率，仍然只作用于已存在的执行片段。

## 契约

- 新增可选字段 `ExecutionBeat.timing?: { sourceIn?: number; rate?: number }`。缺省即旧行为（`sourceIn=0`、`rate=1`），旧存档无需迁移；带该字段的新存档不能被旧代码读取，属前向不兼容，需在文档中声明。
- 取值范围：`sourceIn ∈ [0, 86400)` 秒、`rate ∈ [0.25, 4]`。采样秒为 `min(clip.duration, sourceIn + 镜内局部秒 × rate)`；不做循环、不拉伸、不混合、不做缓动。
- 窗口必须落在片段内：`sourceIn + (beat.end - beat.start) × rate ≤ clip.duration + 1e-6`，否则拒绝并提示所需最大速率或可用的源区间。这样“停在末帧”只会发生在有意让窗口超出片段的旧行为或恰好相等时，不会悄悄冻帧。
- 速率只改片段播放进度，不改根轨迹起止/线性位置、朝向、机位、对白、接触约束与总区间。位置仍按区间进度线性插值，因此高速率不会让人物移动更快。
- 片段资源必须与真实目录一致（索引+名称+时长）；资源变了拒绝，不按名称猜。
- 与既有纠正的互斥：带 `timing` 的片段暂不支持替换片段、拆分或移动静止分界（会改变窗口语义），显式拒绝而不是静默丢弃。反向，源区间/速率纠正只改 `timing`，不动别的东西。
- 审计：沿既有 `manual-performance-correction` 追加记录，`operation: 'retime-beat'`，含前后 `timing`、镜/角色/段、源与场景指纹、人工理由；上限仍 128，超限拒绝。
- 不新增 UI 自动生成、不播放、不写盘、不调用模型、不改存档 schema 版本。采样与几何预检仍在生产应用路径，本契约不构成像素或剧情验收。

## 验证

- `shotExecution` 校验与采样：默认行为不变、非零源区间、慢放、快放、窗口越界拒绝、非法值拒绝、旧计划无 `timing` 仍通过。
- `performanceCorrection.retimeExecutionBeat`：只改所选段、审计记录、资源变化拒绝、无变化拒绝、带 timing 的替换/拆分/分界拒绝、超 128 拒绝、失败不修改输入。
- 组件：面板新增“源区间/速率”暂存路径只进入待确认状态，不应用、不播放。
- 逐文件验证后运行独立全量 Vitest 与 build；不声称 Stage 播放或导出验收。
## 实际结果

- 校验与采样：新增 6 项通过（默认零起点实时行为不变、非零入点、慢速/快速只改片段进度不改根位置、片段末钳制不循环、窗口越界/越界值/未知键/冻结入点拒绝、恰好贴合窗口通过并保留显式字段）。
- 纠正：`retimeExecutionBeat` 新增 7 项通过（只改所选段并写审计 `operation:'retime-beat'`、显式空 `timing` 恢复实时、窗口溢出拒绝且不改输入、非法值/未知键/无变化拒绝、资源变化拒绝、带 `timing` 的替换/拆分/分界显式拒绝、128 条上限拒绝且不驱逐旧记录）。
- 组件：`PerformanceCorrectionPanel` 新增“调整片段源区间与速率”，仅进入待暂存；溢出时禁用暂存；`SetTemplatePanel` 暂存后撤销确认、不应用不播放。定向 11/11（含原 10 项）。
- 首轮失败均为用例自身错误：`rate:.25` 的窗口其实没有溢出（改为 4 倍）；资源变化的报错来自更早的 `assertScriptShotMotionTargets` 英文消息（改为断言抛错）；面板首轮抛 `onRetime is not defined`，是**实现漏了从 props 解构**，补上后通过。
