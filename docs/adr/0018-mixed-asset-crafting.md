# ADR-0018：混合素材合成补齐

状态：已采纳；用户确认推荐方案并记录 ADR。抠图入口、透明轮廓参考图及2D本地工程文件已落地；泼溅双向遮挡仍为已知限制。

## 决定

- 场景内复用现有 image_remove_background 任务，只有显式操作才运行；结果作为独立透明图片平面，不替换原对象，不转成泼溅。使用既有自包含媒体和 v5 平面契约，不为来源信息强制升级格式；旧存档来源不可反推。
- 抠图异步结果受场景代次及原对象存活性保护；锁定对象不允许该操作。离线验收使用模拟任务，不调用真实生成。
- 白模、法线、深度参考图保留媒体平面的纹理 alpha、色键和不透明度轮廓；临时材质逐个释放且不得释放原纹理。原始网格材质行为不变。透明像素拾取不在本轮承诺内。
- 2D 工程先支持本地自包含文件保存/恢复，不复用后端3D存档接口、不新增数据表。包含底图、图片层、层顺序/显隐/透明度及画幅；保留旧2.1格式兼容。载入先完整校验和解码后一次提交，失败不得破坏当前工程。32MiB上限，缺失媒体/超限明确失败，不静默丢层。
- 泼溅双向遮挡先调查现有 Spark 能力并验证可行路线；不直接启用已知破坏半透明边缘的 depthWrite。未获得像素验收前保留单向遮挡限制，不宣称完成。

## 边界

复用既有 React/Three/Konva 与任务接口，不新增框架。不提交推送、不部署、不触碰18000和业务数据库。维持ADR-0015/0016/0017的自包含存档、人工审阅及场景代次隔离。

## 验证

每个文件修改后先验证再改下一文件；添加针对轮廓 shader、抠图异步取消、2D媒体往返及失败不替换的测试；最终运行前端完整test/build。真实后端抠图和泼溅双向像素验收若未执行必须明确列为待验收。

### 仍保留的限制

- 检查当前Spark 2.4.0类型声明：支持自定义vertex/fragmentShader，但没有可直接启用的可靠混合深度合成开关；`depthWrite`文档本身警告大部分Gsplat透明会产生不良结果。不能把开启该参数视作完成双向遮挡。
- 双向遮挡后续需独立深度/覆盖率pass与透明合成，并统一视口、缩略图、截图、首尾帧和序列入口。本轮未实现/验收该管线，不改变既有透明深度设置。
- GLB仍不包含视频与泼溅，三种几何参考图仍不包含泼溅；完整混合资源使用场景存档。FBX/PLY仍需转受支持格式。透明像素射线拾取未纳入本轮。
- 抠图输出按保持原图画布尺寸的现有模板契约放置；如模板裁掉透明边缘需另外约定裁剪偏移。原对象保留且不自动隐藏，用户可在对象列表隐藏原件。真实模板的最终RGBA输出仍待实例验收。
