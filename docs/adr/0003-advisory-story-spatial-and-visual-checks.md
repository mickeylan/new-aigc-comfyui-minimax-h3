# ADR-0003：剧情来源、空间关系与分镜图建议性检查

- 状态：Accepted
- 日期：2026-11-06
- 用户决策：先记录再实施。

## 决策

1. `Scene.Content` 是当前故事正文权威。导演设计、站位、对白分析与提示词是派生产物，不反向替换正文；以正文哈希标识来源。旧数据和已采用媒体保留。
2. 剧情来源一致性检查为只读建议报告：显示输入哈希、已知过期状态、对白覆盖及无法验证的项，不将字面匹配当作剧情完整性的证明，不新增语义生成门禁。拆合镜的操作前后对白比较使用明确输入集合，不猜首末镜。
3. 在既有 `SceneBlocking` JSON 中添加可选、向后兼容的空间/动作关系。明确主体、参照物、人物或摄影参照、物体功能端、运动起止；区分有原文证据的事实与AI建议。分析只预览，显式保存后才进入提示词上下文；正文变化后不使用旧关系。并发预览不可冒充新正文结果。
4. 分镜图检查只使用当前 Scene 的实际图片和可用多模态供应商；不接受任意文件路径或URL，不向文本模型假装输入图片。没有能力时明确返回不可用/无法判断，绝不生成虚假视觉结论。
5. 视觉检查报告区分发现问题、未发现明显问题、无法判断；指出证据、对象和建议，未发现不等于正确性认证。不宣称检查了视频运动或物理规律。
6. 检查不自动修正正文、提示词、站位、图片、视频、任务或审核状态，不创建GPU任务。人工可选择是否采纳建议；生成仍走现有 TaskService、领域审核与模板链路。
7. 不扩张为微服务、新版本系统或通用物理引擎。不增加未提供的Music 3工作流。
8. 检查调用本身仍只读。用户显式保存检查记录时，在Scene上保留最近20条有界历史，标明“用户保存”而非不可伪造的AI审核凭证；记录不是生产审批。来源包括正文、当前关系、图片身份与内容指纹，发生变化后只可查看历史，不可作为当前修正依据。
9. 修正提示词先整理成可编辑预览，不调用GPU；这是将用户保存建议编入现有分镜图提示词，不承诺重新推理消除所有矛盾。用户明确确认后仅保存 `image_prompt` 与过期提示状态，保留故事、镜头、视频和所有媒体；比较预览时的来源与提示词哈希，冲突返回409，不静默覆盖并发编辑。旧格式无法安全处理时拒绝整理而非破坏格式。
10. 拆合镜创建新Scene时不继承旧身份的检查历史；原记录留在归档源Scene。数据库新增字段由既有Scene迁移管理，部署前应备份数据库。

## 实施边界

- 复用现有路由归属检查、配置、供应商能力协商、站位保存和前端场景工作台。
- 检查报告携带来源锚点；前端切换场景、编辑、关闭或发起更新请求时不得展示过期异步结果为当前报告。
- 确定性检查与AI判断分开标示；检查失败不损坏生产数据。
- 相对input图片须校验项目目录、文件签名、大小及实际解析后的路径，禁止符号链接越界；不记录密钥或图片字节。

## 验证

以HTTP与mock供应商验证来源隔离、只读行为、不支持视觉能力、格式错误、失效锚点、跨项目和路径拒绝；以回归测试确认旧JSON兼容、关系经显式保存进入图像/视频提示上下文、原媒体与任务保持不变。真实视觉模型和GPU效果另行验收。
