# ADR-0004：版本化准备阶段与稳定参考绑定

状态：采纳（用户批准三个阶段一起实现，并先记录 ADR）。

## 决策

- 沿用 Go、Vue、SQLite、ComfyUI；新增数据以附加表/带版本 JSON 演进，不迁平台、不破坏旧记录。
- 准备阶段按输入指纹持久化成功、失败和产物。输入相同才复用；失败只重试失败步骤，保留已有成功产物。指纹覆盖实际系统提示、用户输入、模型配置/编译版本与参考内容版本；翻译按分段保存以跨重启恢复。
- 人工编辑与已确认提示词优先；缓存只返回候选，不能绕过现有显式采用。异步结果与采用都核对来源版本，过期返回冲突，不覆盖人工改动。
- 参考选择以来源类型/ID/变体、文件路径和内容 SHA-256 绑定；顺序作为独立信息保留。同名文件内容变更、文件缺失、来源不再可用均显式标记，不能静默替换。旧未绑定数据兼容读取，显式保存时建立绑定。
- 历史提交快照冻结每一位置的文件、内容版本和来源身份，保留重复位置，不能按文件名去重。
- 不改 timeout/retry 策略，不调用真实生成、不批量改写业务数据。剧情锚点仅覆盖视频提示词准备链，非小说改编规划流程。

## 代价与边界

指纹与版本规则是正确性边界，新增有效输入必须同步纳入。文件无法读取不能假装其版本有效。持久产物不含 API 密钥；配置身份只能使用不可逆指纹，不保存凭证。运行中或断线状态不能被当作成功。重复点击和并发应避免同时执行相同阶段；过期产物可保留供审阅，不自动采用。
