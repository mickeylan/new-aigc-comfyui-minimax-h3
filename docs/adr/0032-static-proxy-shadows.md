# ADR-0032：静态代理在阴影与多光源下的等价边界（F3）

- 状态：已实现；jsdom 结构与隔离真实 WebGL 通过，非 Stage 端到端验收
- 前置：ADR-0024 F1/F2

## 契约

代理只在以下条件全部相同时合批：同一材质对象、`castShadow`、`receiveShadow`、图层掩码、`renderOrder`、几何布局。`castShadow` 不同的网格不得进入同一代理，避免阴影相机看到不同对象集合。代理必须复制原件的 `castShadow`/`receiveShadow`/图层/`renderOrder`，并在绘制后立即还原原件可见性与移出代理；不拥有原件几何或材质。

隔离验证：真实 WebGL 下开启投射阴影的方向光与接收面，比较批前/批后读回像素，要求逐像素一致（含阴影贴图路径）；同时验证只让部分网格投射阴影时，代理不会把未投射网格的阴影画出来。

不声称真实 Stage 大场景 GPU/帧率收益、阴影质量改善或跨驱动一致性；不证明透明、自定义材质、骨骼/实例网格或非单位场景变换可合批（这些仍被排除）。不改产品渲染设置、阴影分辨率或光照预设；无 schema/存档/后端/提示词变更，不调用模型，不提交推送。

## 验证

jsdom 结构用例覆盖 shadow 标志分组、代理复制标志、绘制失败还原、单网格不合并；浏览器隔离夹具在开启阴影的真实 WebGL 中回读像素并比较逐通道差。逐文件验证后运行独立全量 Vitest 与 build。
## 实际结果

- jsdom 结构用例4项通过（`staticSceneProxyShadows.spec.ts`，与原 `staticSceneProxy.spec.ts` 15项合跑 19/19 exit0）：`castShadow` 或 `receiveShadow` 不同的网格不进入同一代理且既不合并也不实例化；代理复制 `castShadow/receiveShadow/layers.mask/renderOrder`；非单位场景变换放弃代理并还原原件；仅改一个网格的 `castShadow` 时重建代理（阴影集合随标志变化）。
- 首轮新用例2/4失败，均为我写错期望：代理在 finally 中已移出场景，绘制后 `scene.children` 应为3而非4；把某网格改为投射阴影后，其余两个仍构成合法代理（count 为2），不是“无代理”。按实现既有契约修正新增用例后通过，产品代码未改。
- 隔离真实 WebGL（`frontend/.rscode-f3-shadows.html`，PCF 阴影贴图 512²、方向光投射、地面接收）：3→1 实例代理读回像素与不批时逐通道差0（哈希 2770528015 相同）；把第三个网格改为不投射阴影后，剩2个成批，混合标志场景像素差仍为0（哈希 3972329549 相同）；恢复标志后像素回到基线。原件绘制后可见、代理已移出（`originalsVisibleAfterDraw=true`）。截图 `screenshot-1795838945006.png`；本轮主模型视觉不可用，读数为 sidecar 旁路，三块橙色方块与地面阴影可见。
- 未验证也不声称：真实 Stage 大场景 GPU/帧率与阴影质量收益、跨驱动/跨 GPU 一致性、透明与自定义材质、骨骼/实例网格、多光源下阴影相机数量变化。无 schema/存档/后端/提示词/渲染预设变更，未提交推送。
