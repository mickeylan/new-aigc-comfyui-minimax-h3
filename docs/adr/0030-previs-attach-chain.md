# ADR-0030：链式附着与依赖深度采样顺序（E7）

- 状态：已实现；单元/生产采样/旁档回归与隔离浏览器通过，非Stage端到端验收
- 前置：ADR-0026 E3、ADR-0027 E4/E5

## 背景

E1–E6 明确拒绝“附着目标自身也附着/飞散”。实际预演常见“手里握刀、刀上挂刀穗”这类两层附着，需在不引入通用依赖图/触发器的前提下支持有限链式附着。

## 契约

- 允许 `attach` 的 `targetId` 指向另一个**同时段**处于 `attach` 状态的对象；因此可按依赖深度排序：无依赖的先采样，其后逐层。外部事件清单顺序、旁档内容与 schema 不变，不新增依赖ID字段。
- 依赖只在两个附着事件区间**重叠**时成立；不重叠的先后附着不构成依赖，不做“历史父子关系”推断。
- 采样顺序 = 附着按（深度升序，原序号升序）→ 飞散按原序 → 火烟按原序。深度相同的附着互不依赖，保持外部相对顺序，不声称其像素结果与排列无关。
- 循环依赖（时间上同时生效的 A→B→A 等）在写入时拒绝；同一对象附着/飞散区间重叠沿既有拒绝。
- 附着目标为该对象自身的 `scatter` 时拒绝：飞散是弹道位移，不是稳定父级。
- 运行时对每个附着重新解析实名骨骼；目标对象在本次采样中已按其层级变换定位后，附着使用最新世界矩阵计算。骨骼缺失/重名/目标被移除、锁定、隐藏或换父时整次采样失败并还原，不返回半正确姿态。
- 链式附着只表达“跟随另一被附着对象的实名骨骼”，不代表关节约束、物理接触、闭合握持或释放后弹道接力；`attach` 结束即回编辑姿态，不产生抛掷。不引入通用依赖ID、触发条件或事件图编辑器。
- 不改火烟粒子公式、透明排序、飞散公式、旁档版本、v6/v7 存档或后端；不调用模型；不提交推送。

## 验证

新增链式用例：三层链在乱序外部清单下仍按深度定位、仅两层同时生效时退化为单层、非重叠先后附着不建依赖、写法不同但等价的顺序结果一致、循环拒绝、飞散目标拒绝、链中骨骼缺失失败并还原、采样后 stop 还原全部被触碰对象。原“拒绝链式”断言按本契约有意改为“拒绝循环”，其余断言不变。逐文件测试后运行独立全量 Vitest 与 build；浏览器隔离夹具验证深色界面与两级链实际世界坐标，不称 Stage 剧情验收。

## 实际结果

- `attachSamplingOrder` 在写入时校验循环，并在运行时决定采样次序；附着按深度→原序号，飞散仍原序，火烟最后。旁档复用同一校验，自动兼容链式且未改版本。
- 新用例8项通过（链式两顺序、深度递减、非重叠父级不建依赖、父未生效时子跟随父编辑姿态、循环/飞散父级拒写、缺骨骼或重名绑定期拒绝、采集中途移除失败并还原、生产共享采样器与stop还原、旁档链式往返及循环拒绝），原旁档/事件/UI回归未改。
- **有意变更的测试期望**：原`previsEventDependencies.spec.ts`断言“链式事件拒绝”改为“循环依赖拒绝”，因ADR-0030有意放开有限链式附着；同文件区间重叠与其余断言不变。
- 首轮新用例4/8失败：3项是我自己用例的期望/构造错误（深度序号、父未生效时子的位置、把绑定期拒绝当成采样期拒绝），按契约修正用例后通过；未发现需要改动产品实现的缺陷。
- 独立全量`npm --prefix frontend exec -- vitest run --root frontend` exit0，87文件990/990（`.rscode/e7-final-vitest.log`）；`npm --prefix frontend run build` exit0（`.rscode/e7-final-build.log`）。完整npm test旧Git跟踪import失败保留，未暂存绕过；build不代表完整TS检查。
- 浏览器隔离`frontend/.rscode-e7-chain.html`（真实WebGL、外部清单故意子先父后）：附着前剑[4,1,0]/缎[-4,1,0]，手掌旋转90°后 剑[1,2,0]、缎[1,2,-0.5]（确为父骨骼变换叠加子骨骼偏移）；离开区间后两者与像素哈希均回到附着前（2636063763），会话清单未变，stop后还原。截图`screenshot-1795837796045.png`。本轮主模型视觉不可用，改由可用视觉旁路读取画面并报 JSON（场景物体很小，不作可读性/美术验收），结论以页面实际回读与 readPixels 哈希为准。
